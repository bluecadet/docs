<Features>
  <Feature title="Markdown you already wrote">
    It reads the root README.md and the docs/ tree as-is. Titles come from frontmatter or the first
    heading, relative links between files are rewritten to routes, and images beside a page are
    copied along with it.
  </Feature>
  <Feature title="No project to maintain">
    The CLI ships its own Astro app and its own node_modules. The repo you point it at keeps no
    package.json, no lockfile and no build config — run it from a Go, C# or Rust repo just as
    easily.
  </Feature>
  <Feature title="Navigation and search, derived">
    The sidebar, breadcrumbs, prev/next links and a Pagefind full-text index are all built from the
    file tree. There is no navigation file to keep in sync with reality.
  </Feature>
</Features>

<WillNotDo
  title="Things this will not do"
  accent="will not"
  intro="A short list, kept honest. If one of these is a dealbreaker, better you find out here than after you have moved your docs."
>
  <WontItem lead="Be a CMS.">
    It builds from files on disk. Nothing to log in to, and no copy of your content stored anywhere
    but your repo.
  </WontItem>
  <WontItem lead="Let you restyle it.">
    The palette, typography and layout are the same for every repo that uses it. Configuration
    covers the title, repo URL, base path and extra content globs — not design.
  </WontItem>
  <WontItem lead="Read your source code.">
    There is no API-reference generator here. If you want types or CLI flags documented, write them
    down as markdown like everything else.
  </WontItem>
  <WontItem status="yes" lead="Stay out of your repo.">
    One command in, one output directory out. It never writes back into the tree it read.
  </WontItem>
</WillNotDo>
