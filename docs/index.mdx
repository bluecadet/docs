<Features>
  <Feature title="Config is the source of truth">
    Nothing is discovered by convention. `docs.config.yaml` names the globs that become pages, an
    optional landing file, and everything else about the site — one file to read to know what gets
    published.
  </Feature>
  <Feature title="No project to maintain">
    The CLI ships its own Astro app and its own node_modules. The repo you point it at keeps no
    package.json, no lockfile and no build config — run it from a Go, C# or Rust repo just as
    easily.
  </Feature>
  <Feature title="Navigation and search, derived">
    The sidebar, breadcrumbs, prev/next links and a Pagefind full-text index are all built from the
    routes your config produces. There is no separate navigation file to keep in sync with reality.
  </Feature>
</Features>

<GlyphList intro="A short list, kept honest. If one of these is a dealbreaker, better you find out here than after you have moved your docs.">
  <Fragment slot="title">Things this <em>will not</em> do</Fragment>
  <GlyphItem lead="Be a CMS.">
    It builds from files on disk. Nothing to log in to, and no copy of your content stored anywhere
    but your repo.
  </GlyphItem>
  <GlyphItem lead="Let you fully restyle it.">
    Typography and layout are the same for every repo that uses it. The one design lever
    `docs.config.yaml` exposes is a pair of accent colors — not a general theming system.
  </GlyphItem>
  <GlyphItem lead="Read your source code.">
    There is no API-reference generator here. If you want types or CLI flags documented, write them
    down as markdown like everything else.
  </GlyphItem>
  <GlyphItem glyph="✓" color="var(--accent)" lead="Stay out of your repo.">
    One command in, one output directory out. It never writes back into the tree it read.
  </GlyphItem>
</GlyphList>
